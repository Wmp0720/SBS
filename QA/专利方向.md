#### 三、背景技术

随着大语言模型在搜索助手、智能客服、写作助手等场景的广泛应用，如何高效、客观地评估不同模型在真实用户问题下的表现，已经成为模型迭代与产品落地的关键步骤。

现有的 LLM 评测方法主要包括：

1. **纯人工标注**：由标注员逐条阅读问答数据，对模型回答进行满意度评估与胜负判定。这种方式成本高、效率低，且容易受到标注员主观偏好和疲劳的影响，难以大规模、长期稳定执行。
2. **基于规则/简单打分的自动评测**：利用预定义规则或粗粒度打分模型，对回答进行“对不对”“长不长”等打分。这类方法对复杂多轮对话、主观体验维度（如拟人化程度、阅读体验）刻画不足，且很难对齐真实的人类标注习惯。
3. **单步 LLM 作为裁判**：直接调用一个“裁判模型”，输入用户问题及两个模型回答，输出胜/平/负结论。这种方式虽然自动化程度较高，但存在两个问题：
   1）裁判模型往往比人类更“严格”“挑剔”，与人类标注尺度不一致，导致评测结果不可信；
   2）单步决策缺乏可解释性，无法区分“事实收集过程”和“裁决过程”，难以调试与复用。

此外，在知识问答等事实性任务中，现有评测方法往往只关注回答内容本身，缺乏对信息源可靠性和事实一致性的系统性检测，难以准确识别“看起来很对，但实际上严重错误”的回答。

因此，亟需一种能够：

- 结合历史精标数据自动学习人类标注尺度；
- 拆分“事实收集/问题分析”和“最终裁决”两个阶段；
- 面向知识问答等场景集成信息源事实性检测；
- 支持大规模多线程、可断点续跑的工程化流水线；
  的自动化 SBS 评测方法和系统，实现人机评测风格的一致、结果可解释且具备闭环迭代能力。

#### 四、发明内容（技术方案概述）

本发明提供一种面向大模型对话系统的自动化 Side-by-Side 评测方法及系统，通过“精标数据反思学习 + 四步链路评测流程 + 模糊规则推理 + 信息源事实性检测 + 多线程流水线 + 人机一致性统计”等模块协同，实现对自研模型与竞品模型的高效、可解释、可自适应的自动对比评测。

系统总体包括以下关键模块：

1. **精标数据反思学习模块**：从人工精标的历史数据中抽取代表性样本，构造反思学习 Prompt，驱动评测 LLM 总结人类标注员在不同维度下的“宽容性评测指南”，形成结构化的 learned_guidelines 作为全局评判基线。
2. **四步链路 SBS 评测模块**：对每条用户对话，串行执行：1）单模型主要问题标注；2）主要问题标签到二级满意度的模糊映射；3）基于结构化规则的 CoT 对比分析（只收集事实与问题标签，不下结论）；4）基于“案件档案”的最终胜/平/负裁判。
3. **模糊标签桶与胜负规则推理模块**：利用关键词到“问题桶”的映射表、维度优质前缀识别等手段，对不同格式的标签与自然语言描述进行统一归一，结合 satisfaction_map 和 severity_order 等配置，实现“满意度推理”和“胜负规则判定”。
4. **知识问答信息源事实性检测模块**：专门针对知识问答维度，对模型回答进行 URL/引用识别、信源可靠性判定、联网检索补充权威信息、事实一致性评分，并输出综合评分与等级，将这些检测结果注入到专门的知识问答 SBS Prompt 中，作为判定依据。
5. **多线程评测流水线与断点续跑模块**：支持将大规模评测数据按行分片，多线程并发调用模型评测；通过中间 Excel 文件和 last_success_id 记录实现断点续跑；并对每一步评测过程生成结构化日志和中间结果列。
6. **人机一致性统计与宽松匹配模块**：
   在得到完整的 LLM 评测结果后，对满意度、胜负、主要问题等多个维度，与人工标注进行人机一致性统计；采用宽松的主标签回归/Jaccard 相似度、一致性特例（如 9 与 13 标签的兼容），生成多维度的一致率报告表。

通过上述模块的协同，本发明能够自动、高效地完成大规模 SBS 评测任务，同时在评判尺度上与人类标注员高度对齐，并对知识问答的事实性给出更可靠的判定。

#### 五、具体技术方案（可写入“实施例”）

##### 1. 精标数据反思学习模块

1）系统读取精标数据文件（例如 Excel 格式），筛选包含以下信息的列：

- 用户问题（prompt_content）；
- 自研模型与竞品模型的对话历史与回答内容；
- 人工标注员对自研/竞品的主要问题、对比结论、满意度信息；
- 历史 LLM 评测结果（如有）。

2）系统将上述列裁剪为若干代表性样本，格式化为 Markdown 表格字符串。

3）构造特定的反思学习 Prompt，包括但不限于以下要素：

- 明确角色设定为“经验丰富的互联网标注员/评测元分析师”；
- 强调“抓大放小、以用户体验为核心”的评判思维；
- 引导模型对比“标注员_”字段与“LLMs_”字段的差异，特别关注人类在何种情况下仍给出“无问题/合格”；
- 要求模型输出一套条目化的“宽容性评测指南”，用于后续评测。

4）调用外部大模型接口，获取反思学习结果，将其以文本形式写入规则配置（rules['learned_guidelines']）。

5）之后所有评测 Prompt（单模打标、SBS 分析、最终裁决等），在构造时均注入该 learned_guidelines，使评测逻辑自动向人类习惯对齐。

##### 2. 四步链路 SBS 评测模块

针对每条数据（用户对话及双模型回答），系统依次执行以下步骤：

**步骤 S1：单模型主要问题标注**

- 分别提取自研模型和竞品模型的多轮对话历史与当前轮回答，构造成包含“上下文 + 本轮问答”的文本。
- 使用 `create_single_model_prompt` 构造单模标注 Prompt，注入当前度量维度说明、优质标签集合、单个大模型主要问题标签全集、learned_guidelines 以及失败触发器知识库。
- 调用评测 LLM，解析其输出为结构化 JSON，至少包含：
  - “主要问题”：从预定义标签集中选取 1–3 个；
  - “优质弱智主要问题”：若为弱智/优质时给出具体原因标签；
  - “标注理由”：简要说明。

**步骤 S2：主要问题到二级满意度映射**

- 将步骤 S1 输出的“主要问题”标签字符串输入 `map_main_issues_to_satisfaction`：
  - 先通过 `_split_labels` 将中文逗号等分隔符拆成标签集合；
  - 使用 `bucket_of` 函数基于关键字映射、维度优质前缀、弱智/优质显式前缀等，将标签归一到有限的“问题桶”；
  - 使用配置中的 `satisfaction_map` 与 `severity_order`，从严重到轻微匹配桶名，推理出“弱智/不合格/合格/优质/未选中”的满意度等级，并输出命中模式原因。
- 将满意度等级和原因写入中间结果列，用于后续统计与裁决。

**步骤 S3：CoT 第一步——SBS 对比分析**

- 基于自研/竞品的上下文与当前轮回答，构造 `create_sbs_analysis_prompt`：
  - 明确角色为“证据书记员/分析员”；
  - 强调只做事实收集与标签标注，不进行胜负裁决；
  - 要求输出 JSON，字段包括：
    - “大模型A_SBS主要问题”、“大模型B_SBS主要问题”：从 SBS 标签集合中选取多标签；
    - “大模型A_命中的失败触发器”、“大模型B_命中的失败触发器”：从 loss_triggers 中选取；
    - “大模型A_符合的胜利模式”、“大模型B_符合的胜利模式”：从 win_patterns 中选取。
- 调用 LLM，解析输出，形成结构化“案件档案”analysis_json。

**步骤 S4：CoT 第二步——最终裁决**

- 将 analysis_json 以及步骤 S1 得到的单模主要问题作为输入，构造 `create_final_judgment_prompt`：
  - 明确角色为“高级评测法官”；
  - 详细列出“致命错误优先、优势模式优先、问题严重性/数量对比、无法区分则平局”等判定规则；
  - 要求仅输出 JSON，字段包括“ 大模型A竞品对比”（胜/平/负）与“裁判说明”。
- 调用 LLM，解析最终裁决结果，并与前述中间结果整合为统一的输出结构。

##### 3. 模糊标签桶与胜负规则推理模块

1）系统维护一个关键词到桶名的映射表 KEYWORD2BUCKET，将非规范标签或自然语错误描述归一为有限的“问题桶”，如“内容错误”“事实性错误”统一映射为“2内容质量差_1.内容错误”。

2）通过 `bucket_of` 函数按以下优先级处理标签：

- 若标签前缀为某些维度优质前缀，则直接归为“14优质”；
- 若标签已含“12弱智”“14优质”“13无问题”等前缀，则直接归为对应桶；
- 否则依次匹配 KEYWORD2BUCKET 中的关键字，或根据包含关系回退到更粗粒度桶（如“内容质量差”）；
- 最后兜底为“标签字符串下划线前的主类部分”。

3）在满意度推理中，遍历从“弱智”到“优质”的等级，并结合 labels 原始字符串前缀与 bucket 前缀匹配，确定最合适的满意度等级。

4）在胜负自动规则判断中，通过 `_top_severity_bucket` 获取每一方最严重问题桶及其数量；再依据 severity_order 比较严重级别和数量差异，如仍无法判定，则统计总问题数，最后若仍无法区分则返回需裁判模型介入的标志。

##### 4. 知识问答信息源事实性检测模块

1）针对知识问答维度，系统在常规 SBS 流程基础上，引入 `SourceChecker` 与 `KnowledgeQAJudge` 组件。

2）`SourceChecker` 执行以下步骤：

- 从回答文本中用正则表达式提取 URL、书名号引用等潜在信息源；
- 基于 reliable_keywords / suspicious_keywords 对引用做初步可靠性分类；
- 利用联网大模型接口，以“问题核心主题”为查询词，检索 3–5 条权威信息源，输出标题、URL、摘要；
- 构造核查 Prompt，对回答与补充信息源进行事实一致性对比，输出事实性评分、一致性评分、可靠性评估与改进建议；
- 线性加权计算综合评分与评分等级。

3）`KnowledgeQAJudge` 在获取信息源检测结果基础上：

- 依据预设权重对准确性、专业性、时效性、格式、详略得当、逻辑、回复风格等维度打分并线性加权；
- 对特定严重情形（如事实性评分极低、存在显著错误描述、回答明显拒绝或无法作答）直接给出“弱智”判定及对应主要问题标签；
- 将综合评分映射为“优质/合格/弱智”及相应主要问题标签；
- 构造知识问答专用 SBS Prompt（包含两方回答、信息源文本、综合评分与规则说明），由裁判模型输出统一格式的 SBS 结果。

##### 5. 多线程评测流水线与断点续跑模块

1）读取输入数据集 Excel，将全表切分为若干子 DataFrame，以线程数为粒度分配给各线程处理。

2）每个线程内：

- 通过 `initialize_output` 为子集构造输出文件路径、日志文件路径、终端输出文件路径和 `last_success_id.txt`；
- 若已有中间 Excel，则优先加载并从最后成功行开始续跑，实现断点续跑；
- 逐行调用前述四步评测流程，将所有中间结果与最终结果写入该线程的输出 Excel；
- 在任一行处理完后，立即更新输出文件与 `last_success_id.txt`，并更新统一进度条。

3）主线程在所有子线程结束后，通过 `merge_thread_outputs` 搜索并按文件名排序合并各线程输出文件，生成完整的评测结果文件。

##### 6. 人机一致性统计与宽松匹配模块

1）系统读取最终评测结果 Excel，将原始人工标注列与 LLM 评测列统一规范化（字段名兼容）。

2）在去除标记为“剔除”的数据后，计算以下指标：

- 满意度（0/1 合格率）一致率；
- 满意度等级（弱智/不合格/合格/优质）一致率，包含特殊处理：若一方为“9”另一方为“13”，视为一致；
- 胜负平标签一致率；
- 主要问题标签一致率：
  - 将多标签字符串按逗号拆分并回归到一级标签，
  - 采用行级交集/Jaccard 规则：有交集即视为一致，并对“9/13”等特殊组合做豁免；
- 各维度（一级/二级分类）上的分组一致率；
- 按竞品、标签的召回率与精确率。

3）把上述统计结果写入新的 Sheet，包括：总体人机一致率、分维度一致率、分竞品指标、0/1 召回率精准率、胜负平召回/精准率、主要问题一致率等多张表，便于分析和展示。

#### 六、本发明的有益效果

与现有技术相比，本发明具有以下显著有益效果：

1. **评测尺度自动对齐人类标注习惯**：通过“精标数据反思学习 + learned_guidelines 全流程注入”，使评测 LLM 从“过于挑剔”调整为“抓大放小、贴近真实用户感受”，显著提升自动评测结果与人类标注的一致性。
2. **评测流程可解释、可拆解**：将 SBS 裁判拆解为“单模打标 → 满意度映射 → CoT 分析 → CoT 裁决”四步，使每一环节均有明确中间结果（问题标签、失败触发器、胜利模式、裁判说明等），方便调试、复盘和规则更新。
3. **支持模糊标签与复杂规则推理**：通过关键词桶、severity_order、多级比较等机制，能够容忍标注标签的噪声和多样性，自动推理模型满意度等级与胜负结论，减少人工规则维护成本。
4. **针对知识问答场景的事实性与信息源保障**：集成引用分析、联网检索、事实一致性核查和综合评分，将“看起来合理但实际错误”的回答识别出来，为安全性要求较高的领域（医疗、法律、金融等）提供更可靠的评测依据。
5. **工程化的大规模评测能力**：通过多线程流水线、断点续跑、中间结果持久化和日志体系，能够在资源受限和网络不稳定的环境下稳定完成大规模评测任务。
6. **系统性的人机一致性评估与优化闭环**：
   提供多视角的人机一致性指标与报表，帮助评测团队快速定位哪类维度、哪类问题标签与人类差异最大，进而针对性地优化规则、Prompt 或模型。
